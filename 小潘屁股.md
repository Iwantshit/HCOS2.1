**4. ResourceManager 重构（关键）**

ResourceManager 当前职责偏重（resources.py:15-47），同时承担了
状态存储（_res 字典）
事件广播（bus.publish）
缓存同步（cache.set）
隐式对象语义（通过 resource_id 表示设备）

改造

不替换 ResourceManager，而是拆分职责：

1、保留 ResourceManager：
继续负责状态存储、事件广播、缓存同步。

2、新增 EntityRegistry：
专门负责实体对象管理及实体与设备的映射关系。

    # core/entity_registry.py
    class EntityRegistry:
        def __init__(self):
            self.entities = {}      # entity_id -> Entity
            self.by_device = {}     # device_id -> set(entity_id)
    
        def register(self, entity):
            self.entities[entity.entity_id] = entity
            if entity.device_id:
                self.by_device.setdefault(entity.device_id, set()).add(entity.entity_id)
    

协作方式：

EntityRegistry 管理实体对象

ResourceManager 管理实体状态数据

**6. 双命令模式支持**

系统目前仅支持事件驱动控制模式（light.py:96-116，main.py:93-95）：

控制方式依赖 bus.publish(Event("cmd.light.on", {...}))

无法直接调用实体方法

不支持同步返回执行结果

改造

在 kernel.py 中新增统一服务调用接口：

    async def call_service(self, entity_id: str, service: str, data: dict = None):
        entity = self.entity_registry.get(entity_id)
        if entity:
            method = getattr(entity, f"async_{service}", None)
            if method:
                return await method(**(data or {}))

        # 兼容旧插件，回退到事件模式
        await self.bus.publish(Event(f"cmd.{entity_id}.{service}", data or {}))


由此同时支持：

直接实体调用（新模式）

事件驱动控制（兼容旧插件）
